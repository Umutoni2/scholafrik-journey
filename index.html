Meet ScholAfrik

Context for the work — keep this editable and accurate.

ScholAfrik (logged as Scholarfrik in my immersion cover page) is the company context for my Frontend Developer Internship during Skills Immersion 1.

Program: Skills Immersion 1 | ALCHE | 2025 Oct Term

Supervisor: Dadeboe Perez

As a Frontend Developer Intern supervised by Dadeboe Perez, I implemented user-facing pages and flows in Next.js/React — from marketing and community UI to authentication, API-connected features, and internal-style dashboards.

Each week included progress meetings, technical discussions, and reviews — presenting work, discussing challenges (auth, responsiveness, APIs, local state), and aligning on next steps with the team.

Contribute front-end experiences that help students discover community, scholarships, research, and account flows — while building a portfolio of real, reviewable work.

  • Share progress in team meetings and act on review feedback

What I Built

Students & Connection Goals

  • React
  • TypeScript
  • Tailwind CSS
  • Next.js
Problem
Landing/community surfaces needed reusable student presentation and clear connection-goal navigation.
My contribution
Built reusable student cards and horizontal carousel from shared student data; built responsive connection goals grid and utilities.
Challenge
Keeping cards/carousel/goals reusable while matching responsive design expectations.
Solution
Shared data + reusable components/utilities; tested icons/layout before PR.
Result
Students and Connection Goals section completed and submitted through GitHub.
Reflection
Reusable building blocks save time and keep the product consistent as features grow.

Scholarships listing page

  • Next.js
  • React
  • TypeScript
  • Tailwind CSS
Problem
Users needed a responsive scholarships experience with listing, supporting content, and useful filtering/deadline helpers.
My contribution
Built hero + listing, impact/FAQ/contact/CTA sections, and TypeScript filtering/deadline utilities with unit tests.
Challenge
Design consistency across many sections while adding tested utility logic.
Solution
Section-by-section implementation against the design reference; unit tests for utilities; full responsive pass.
Result
Responsive scholarships page shipped; linting and TypeScript validation passed.
Reflection
Utilities deserve tests too — not only visible UI.

About page

  • Next.js
  • React
  • Tailwind CSS
  • Next.js Image
Problem
ScholAfrik needed a polished /about story: hero, stats, mission/vision, team, and why-us content.
My contribution
Structured /about with existing Navbar/Footer; built Hero, Stats, Mission/Vision, Team, Why ScholAfrik; configured optimized images.
Challenge
Runtime issues and external image loading while staying responsive.
Solution
Debugged locally across breakpoints; fixed image configuration and layout issues before PR.
Result
Responsive About page completed and verified on localhost.
Reflection
Reusing shared chrome protects brand consistency; image config is part of front-end quality.

Login & Authentication

  • Next.js
  • NextAuth
  • React
  • TypeScript
  • Tailwind CSS
Problem
Users needed secure sign-in (email/password + Google) and correct routing based on profile completion.
My contribution
Login UI; NextAuth credentials flow with error/loading states; Google OAuth/callback; profile checks routing to onboarding or feed; conflict resolution.
Challenge
Merge conflicts while preserving existing OAuth and callback behaviour.
Solution
Integrated within existing auth architecture; tested sessions and redirects carefully after merges.
Result
Credentials + Google auth and profile-based routing working together.
Reflection
Authentication work is product-critical — protect the existing flow while you extend it.

Auth-aware navbar & feed polish

  • React
  • NextAuth
  • Tailwind CSS
Problem
Guests and signed-in users needed different navigation; feed UI needed clearer hierarchy and empty states.
My contribution
Session-based navbar states; avatar dropdown with initials fallback; profile/feed/settings + sign-out; feed visual polish.
Challenge
Correct behaviour across logged-in/out states, refresh, and responsive layouts.
Solution
Conditional rendering from session; explicit testing of sign-out and navigation paths.
Result
Clearer auth-aware navigation and a more usable feed UI.
Reflection
Front-end quality is often the sum of state-aware details users feel immediately.

Partners API (BackOffice)

  • TypeScript
  • REST APIs
  • React
  • Git/GitHub
Problem
BackOffice needed reliable partner listing, creation, status updates, and deletion against the API.
My contribution
Implemented GET list with pagination/filters, POST create, PATCH/DELETE with delete confirmation inside existing structure.
Challenge
Understanding existing hooks/components and debugging full request/response cycles.
Solution
Incremental API operations, confirmation for destructive actions, tests against existing UI wiring.
Result
Partner CRUD-style operations integrated; stronger grasp of frontend–backend collaboration.
Reflection
UI work is incomplete until the API contract is understood and verified.

Scholarships & Research dashboards

  • React
  • TypeScript
  • Tailwind CSS
  • Next.js
Problem
Internal-style dashboards were needed for scholarships and research with filters, tables, actions, and create modals.
My contribution
Built both dashboards with summary cards, filters, tables, row actions, badges, and add modals using local mock state only; added Research route/sidebar.
Challenge
Matching the hosted UX reference while implementing full interactions without backend changes.
Solution
Followed existing mock-data pattern (data.ts unchanged); managed interactions with useState; iterated on visual details.
Result
Both dashboards usable with search/filter/actions/modals and improved visual consistency.
Reflection
Local state is enough to prove UX — when conventions say not to touch the backend yet.

Chapter 10

Product Quality

A product is not successful simply because the code works.

  • Be useful
  • Be reliable
  • Be consistent
  • Be easy to use
  • Look good
  • Solve the user’s problem

Good Design

Matched ScholAfrik design references for scholarships, About, login, feed, and dashboards.

Durability

Reusable cards/utilities and shared Navbar/Footer/auth components reduce fragile one-offs.

Consistency

Visual consistency work on feed and dashboards — badges, spacing, buttons, empty states.

Reliability

Auth error/loading states, delete confirmation, conflict-safe merges, and retested sessions.

Functionality

Filtering, deadlines, OAuth, partner CRUD operations, dashboard search/filters/actions.

After-Sales Support

Weekly reviews and fixes after demos — treating feedback as continued care for the product.

Value for Money

Ship useful student-facing and ops-facing UI that respects user time and real workflows.
